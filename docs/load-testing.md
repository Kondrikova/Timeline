# Нагрузочное тестирование Timeline

SLO объявлены до прогона (см. `docs/architecture.md` §16). Скрипты — в `k6/`.

## Целевые SLO

| Сценарий | Цель |
|---|---|
| `GET /api/v1/timeline/board` | p95 < 300 мс при 50 RPS |
| `POST .../move` с `preview=true` | p95 < 1 с |
| Пересчёт плана | < 5 с на демонстрационном объёме |

## Как прогонять

См. `k6/README.md`. Окружение: `docker compose up --build`, затем токен ADMIN.

## Результаты

| Дата | Скрипт | p95 board | 304 rate | Ошибки | Вердикт |
|---|---|---|---|---|---|
| _заполнить после прогона_ | board-load.js | | | | |

## Выводы

- Эффективность ETag: доля `304` фиксируется метрикой `board_etag_304`.
- Отрицательные результаты тоже документируются: если p95 выше SLO на холодном
  кэше Mongo — указать, что прогрев проекции обязателен перед демонстрацией.

_Шаблон заполняется после реального прогона на машине с Docker и k6._
